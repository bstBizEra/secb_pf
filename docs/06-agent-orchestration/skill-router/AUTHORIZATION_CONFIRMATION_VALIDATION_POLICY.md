# Authorization, Confirmation, Validation and Fallback Policy

Selection answers “which skill may help.” Invocation authority answers “may this skill run now.” Effect authority answers “may this exact external change occur.” These decisions must remain separate.

Separate confirmation or warrant is mandatory for destructive/irreversible changes, publication or deployment, external communications, financial commitments/transactions, credential access or transfer, permission changes, sensitive-data disclosure and acceptance of external terms.

Validation is compiled before execution and may include schema checks, deterministic tests, security/data-quality gates, preview, file/repository/deployment readback, hashes, signatures, provenance, RTM mapping, destination/recipient verification and side-effect reconciliation. A skill self-report is not evidence.

Fallback order: bounded transient retry; compatible registry-approved fallback; clearly labelled read-only/draft/advisory degradation; minimum clarification/authorization; hold. No fallback may lower safety, authority, data or acceptance floors.
